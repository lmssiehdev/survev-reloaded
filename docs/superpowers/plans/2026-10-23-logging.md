# Logging (LogTape + Axiom) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace all existing logging with a LogTape-based `@survev/logger` package that writes structured records to stdout and ships them to Axiom, plus a small set of event records, without slowing the game loop.

**Architecture:** `packages/logger` owns LogTape setup, a JSON record format, an Axiom HTTP batch sink and crash handlers. It takes plain options (no config import); each app calls `setupLogging` with values from `sharedEnv`. The game package keeps its dependency-free `GameLogger` interface and gets a LogTape logger injected. Old loggers, Discord webhooks and client error reporting are migrated off, then deleted.

**Tech Stack:** Bun, TypeScript, `@logtape/logtape`, Hono (API), zod env parsing, `bun test`.

**Spec:** `docs/superpowers/specs/2026-10-23-logging-design.md`

## Global Constraints

- Branch `logging` (off `env-config`). Commit after each task. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Settings are env vars in `packages/config/env.ts` (`sharedEnv`) and documented in `.env.example`. No config files.
- Env vars: `LOG_LEVEL` (`debug | info | warning | error`, default `info` in prod, `debug` in dev), `LOG_FORMAT` (`pretty | json`, default `json` when `isProd`, else `pretty`), `AXIOM_TOKEN`, `AXIOM_DATASET` (both optional, Axiom sink only when both set), `SURVEV_ENV` (`production | staging | dev`, default `dev`).
- Axiom ingest: `POST https://api.axiom.co/v1/datasets/<dataset>/ingest`, `Authorization: Bearer <token>`, `Content-Type: application/x-ndjson`. Flush every 2000 ms or 500 records, whichever first. Max queue 10000 records, drop oldest on overflow.
- Axiom sink failures go to `console.error` directly, never through LogTape.
- `packages/game` must not import `@logtape/logtape` or Node-only modules.
- Inside `Game.update` / `Game.netSync`: only counters and ring-buffer writes; no logger calls except the throttled slow-tick warning.
- Logger categories are arrays rooted at `"survev"`: `["survev", <app>, ...]`.
- Logging tests live in `packages/logger/test/` and run with `bun test`. No other new test files.
- Use exact LogTape APIs from the installed version's `.d.ts` (`configure`, `getLogger`, `fingersCrossed`, `fromAsyncSink`, `getConsoleSink` `nonBlocking`, `withContext`, `contextLocalStorage`, `dispose`). If LogTape's `Logger` has no `warn` alias, add one in the adapter in Task 3.

## Review Focus

- Axiom down / returns 500 / fetch throws: the process keeps running, records are dropped with one `console.error` per failed batch, no logger recursion. Test in Task 2.
- Error with a `cause` chain, an Error nested inside a props object, and a circular object: serialized without throwing. Test in Task 1.
- Crash from an unhandled promise rejection: `process.crash` is logged with `kind: "rejection"` and buffered Axiom records are flushed before `process.exit(1)`. Test in Task 3.
- Unset `AXIOM_TOKEN`/`AXIOM_DATASET` (local dev, tests): no Axiom sink, no network, stdout only. Test in Task 3.
- A game where every tick is slow (overloaded server): at most one slow-tick warning per 10 s per game, carrying `suppressed` count. Test in Task 6.

### Task 2: Axiom batch sink

**Files:**
- Create: `packages/logger/axiomSink.ts`
- Test: `packages/logger/test/axiomSink.test.ts`

**Interfaces:**
- Consumes: `recordToJson` (Task 1).
- Produces: `createAxiomSink(opts: AxiomSinkOptions): Sink & AsyncDisposable` with
  `AxiomSinkOptions = { token: string; dataset: string; fetch?: typeof fetch; flushIntervalMs?: number /*2000*/; batchSize?: number /*500*/; maxQueue?: number /*10000*/ }`.
- Behavior: sink call pushes `recordToJson(record)` into a queue (sync, no await). Flush when queue ≥ `batchSize` or on the interval timer (`unref()`ed). One in-flight request at a time. Overflow drops oldest and increments a counter; the next successful batch's first line is a record `{ level: "warning", message: "logger.dropped", dropped: n }`. Failed request (throw or non-2xx) → `console.error("axiom ingest failed", status|err)`, batch discarded. `[Symbol.asyncDispose]` flushes everything remaining and clears the timer.

- [ ] **Step 1: Write failing tests** using a fake `fetch` that records calls:
  - 3 records, `flushIntervalMs: 20` → after 50 ms, exactly 1 call, URL `https://api.axiom.co/v1/datasets/ds/ingest`, header `Authorization: Bearer tok`, body is 3 NDJSON lines.
  - `batchSize: 2`, 2 records → flushes without waiting for the timer.
  - `maxQueue: 3`, fetch blocked until released, 5 records → after release, the shipped lines include a `logger.dropped` record with `dropped: 2` and the 3 newest records.
  - fetch returns 500 → `console.error` spied called once; a later record still ships.
  - fetch throws → no throw escapes the sink call; `console.error` called.
  - `await sink[Symbol.asyncDispose]()` with 1 queued record → 1 call made before resolving.
- [ ] **Step 2:** Run `bun test packages/logger/test/axiomSink.test.ts` → FAIL.
- [ ] **Step 3:** Implement `createAxiomSink`.

### Task 3: `setupLogging`, crash handlers, flush

**Files:**
- Create: `packages/logger/index.ts`
- Test: `packages/logger/test/setup.test.ts`

**Interfaces:**
- Consumes: `createAxiomSink`, `recordToJson`.
- Produces:
  - `type AppName = "api" | "game-server" | "game-proc" | "bot"`
  - `setupLogging(opts: { app: AppName; level: "debug" | "info" | "warning" | "error"; format: "pretty" | "json"; env: string; git: string; region?: string; axiom?: AxiomSinkOptions; console?: boolean /*default true*/ }): Promise<void>`
  - `getLogger(category: string[]): AppLogger`: LogTape logger whose category is `["survev", ...category]`, with a `warn` alias if missing.
  - `withContext` re-exported from LogTape.
  - `flushLogs(): Promise<void>`: disposes LogTape (flushes console buffer and Axiom sink).
  - `installCrashHandlers(): void`: `uncaughtException` and `unhandledRejection` → `getLogger(["process"]).fatal("process.crash", { kind: "exception" | "rejection", err })`, `await flushLogs()`, `process.exit(1)`.
  - `logProcessStart(props?: Record<string, unknown>)` / `process.exit` hook: logs `process.start` once; on `SIGINT`/`SIGTERM` logs `process.exit` with `signal`, flushes, exits with 130/143.
- `setupLogging` config:
  - Root logger `["survev"]` with `lowestLevel: "debug"`; static properties `app`, `env`, `git`, `pid`, `region` (only if given) are added to every record (via a wrapping sink or implicit context, builder's choice; must apply to child process records too).
  - Sinks: console (`nonBlocking`, `pretty` = human one-liner `HH:MM:SS LEVEL category message {props}`, `json` = `JSON.stringify(recordToJson(r))`) and Axiom (if `opts.axiom`), both wrapped in one `fingersCrossed` that: always passes records ≥ `opts.level`; buffers records below it (max 200 per context) isolated by context keys `["gameId", "requestId"]`; on a `warning`+ record in the same context, emits the buffer first.
  - `contextLocalStorage: new AsyncLocalStorage()`.
